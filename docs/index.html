Where this sits in the exploitation chain

  1. Reach OOM inside the declared limitsdemonstrated
    A small multipart body exhausts memory_limit while staying far inside post_max_size, during request startup.
  2. Control content, location and timing of the corrupted memorynot demonstrated
    Heap grooming against both glibc malloc and Zend's allocator, so the invalid state contains attacker-chosen bytes.
  3. Turn a read into a jumpnot demonstrated
    The stale value must be used as a pointer, length or index — plus an information leak to defeat ASLR/PIE.
  4. Bypass mitigationsnot demonstrated
    NX requires a ROP chain; stack canaries and CET/shadow stack add further constraints.
  5. Make it reliablenot demonstrated
    Consistent exploitation across a multi-worker prefork pool under normal traffic.

No public proof-of-concept exists for stages 2–5. A successful RCE yields code execution as the web worker account (www-data), not root — privilege escalation is a separate step.
